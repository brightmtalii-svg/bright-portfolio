# Recovery Notes — Bright Portfolio

## Original Windows filesystem recovery

The original project was recovered from a damaged Windows volume. Recovered
raw fragments remain under `D:\found.000` and were left **untouched** by this
reconstruction. All work for version control was performed only in the
restored directory listed below; no recovered filesystem data was modified or
deleted.

## Reconstructed project location

- Restored application: `D:\Bright-Portfolio-Restored`
- Original recovery source: `D:\found.000` (read-only reference, not tracked)
- Source of ambiguous recovered artifacts: `.archive/` and `review/` (excluded
  from version control)

  - API routes: `/api/ask`, `/api/contact`

## Remaining known issues

- `review/ambiguous-files/bright-mtalii.jpeg` is an alternate, non-active
  profile image retained only for manual comparison. The application references
  `bright-mtalii.jpg`. This directory is intentionally excluded from version
  control.
- `.archive/` contains a pristine recovered scaffold copy kept for audit
  purposes only and is excluded from version control.
- `.env.example` contains placeholders only; real deployment values must be
  supplied in `.env.local` / hosting environment variables.
- `README.md` references `RECOVERY_REPORT.md`, which is not part of this
  repository; `RECOVERY_NOTES.md` supersedes it.
- Generated files (`next-env.d.ts`, `*.tsbuildinfo`, `.next/`) are git-ignored
  and will be regenerated by the toolchain.

## Version-control notes

The initial commit intentionally excludes `node_modules/`, `.next/`,
`.archive/`, `review/`, `scripts/tmp/`, environment secrets, and generated
build caches. `.env.example` is preserved so contributors can recreate local
configuration.
